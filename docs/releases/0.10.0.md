# Method Budget 0.10.0

In a shared budget, each person's name is now signed by their own computer and each role is
tied to that person's key, and every update is checked more closely before it installs.
Everyone who shares a budget should update together.

## Update everyone who shares a budget together

- **Shared budgets move to a new format.** Once someone on 0.10.0 opens a shared budget that
  has roles, it moves to a new format, and Method Budget 0.9.0 and older can't read it.
- **What someone on an older version sees.** Their app still opens the budget's file, on its
  own. It says the shared changes are newer than it reads, and nothing they change there is
  shared.
- **So update first.** Before you open a shared budget in 0.10.0, make sure everyone who
  shares it has 0.10.0 too. Help > Check for Updates gets it.

## Shared budgets you can trust

- **Names are signed.** Each person's name and color are signed by their own computer, so the
  People list, requests, Activity and Who Changed This show the name that person gave
  themselves. A name that isn't signed yet says so.
- **Roles are tied to each person's key.** A role you give is tied to the key of that person's
  computer, and someone joining from an invite link is tied from the start.
- **Confirm a key once.** For someone who had a role before this version, the Share dialog
  offers Confirm key…. Read them the code it shows, by phone or in person, and they read back
  the code their own app shows. If the two match, their role is tied to their key.
- **Requests show what to check.** An access request shows a code for the asking computer,
  and says when the name is also someone else's, when the computer is new to the budget,
  when the person was removed, or when no key in their name is in the budget yet. For a
  request like that, Allow asks once more.

## Updates you can trust

- **Checked before they install.** On a Mac, an update is installed only if the new copy is
  signed by the same developer as the app you have. If it isn't, it's left out and your copy
  stays as it is.
- **No going back.** Once a version has been downloaded and checked, an older one is never
  offered in its place.

## Steadier with big and shared budgets

- **Big budgets edit smoothly when shared.** Editing a shared budget with many thousands of
  transactions no longer needs a great deal of memory for each change.
- **Shared folders are read with care.** A damaged or unexpected file in a shared folder is
  now refused, instead of stopping autosave or the app.

## Schedule days fill in your dates

- **Prep, shoot and wrap dates come from the schedule.** File > Import Schedule Days… now also
  fills in the budget's prep start, shoot start, shoot end and wrap end, alongside the day
  counts, and lets you choose which to take.

## Fixed

- **Charts of accounts with accented numbers.** Importing a budget export whose account
  numbers have letters with accents, or from other alphabets, no longer stops the app.
- **Pinned projects.** In the start window, Show Folder for a pinned project that is an app
  or a package now shows it in its folder instead of opening it.

## Good to know

- **Live changes are still held back.** Sharing works through a shared folder, as before.
- **Mac builds are universal.** Windows and Linux builds are included but not yet tested by
  hand. The Windows build is not signed, and no certificate is planned: Windows warns that the
  publisher is unknown before it opens.
